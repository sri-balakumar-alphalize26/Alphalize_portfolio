## What shipped

### Brand switcher (`f1c9d96`)

Hovering the header logo opens a two-row panel: Alphalize, and 369AI in a new tab. The logo comes in through a slot rather than sitting beside the switcher — a sibling arrangement would have left the logo outside the hover target, and hovering the logo *is* the feature.

Three departures from the `LocaleSwitcher` pattern it copies, each for a reason:

- `pointerout` is gated on a fine pointer, and the click handler clears the pending timer. On touch the order is pointerup → pointerout → click, so an ungated close fires 180 ms after the tap that opened it. `LocaleSwitcher` still has this bug.
- A `focusin` handler closes it when focus leaves. Escape was covered; tabbing past the last row was not.
- The panel id is generated. `LocaleSwitcher` hardcodes `id="ls-panel"` and mounts twice per page, so every page shipped a duplicate id with one `aria-controls` pointing at the wrong node.

### A whole class of dead CSS (`3a18572`)

In this Astro version a child component's root does **not** inherit the parent's scope hash. The compiler still passes it as a prop; a hand-written component drops it unless it spreads rest props. `<Image>` does spread — which is why image rules were the only ones still working, and why nobody had noticed.

Every rule a parent wrote for a class it handed to a child was dead:

| Rule | Effect |
|---|---|
| `.ls-flag`, `.ls-flag-lg`, `.ls-chev`, `.ls-check` | Flags and icons rendering at **~225 × 150 px** — the CSS default object size for an unsized SVG |
| `.bs-chev`, `.bs-check` | Same, beside the logo |
| `.hdr-ls` | `display: none` never applied, so the desktop language switcher **showed on mobile too**, beside the drawer's own copy |
| `.apply-f` | The focus underline on five careers-form fields |
| `.brand` + 4 stagger selectors | Chevron skipped the header entrance |

Fixed once at the cause: six components now forward rest props. `Flag.astro` also gained a default size — it was the only component with no intrinsic-size defence, which is what turned a missed rule into a 225 px flag rather than a small slip.

Three topics were reframed because the site makes no such claim anywhere — there is no e-commerce offering, and nothing about guiding videos or user manuals. Those lean on copy the site does carry instead.

### astro 7.3.2 (`c88ba79`)

Every prerendered route was returning **500** in dev — `/en`, `/en/about`, all of them — while on-demand routes worked. 7.3.1 installed its own default fetch handler unconditionally and then tested it with `instanceof`, which fails across Vite's dep-optimizer boundary; the app then discarded its own manifest and looked routes up in a map that by design holds only on-demand routes.

7.3.2 gates on the `isDefaultFetchHandler` marker export that already existed for the purpose. Upstream fix, exactly matching the trace.

### Locale-losing links + a checker (`b3c5b43`)

Seven places emitted an unprefixed href, and the 404 page's language switcher pointed at `/{locale}/404`, which is never built.

An unprefixed link fails twice, and neither shows in a passing build. In dev it is a hard 404 — `_redirects` is a Cloudflare feature the dev server never reads. In production it 301s to `/en/…`, so an Arabic reader clicking an Arabic page's button lands on the English one, locale silently gone.

`scripts/check-links.mjs` guards it now. **My first version passed the bug** — `/services/*` has a redirect rule, and "it redirects" looked like "it is fine", which is precisely what hid these. It now treats any anchor without a locale prefix as an error whatever the rules say.

### 80 KB off the homepage (`b3c5b43`)

471 inline SVGs drawn from 63 distinct shapes — 160 KB, 47% of the document. Two shapes were 99 KB of it: the review star (5 × 54 cards) and the card's hand-drawn "66" mark (4 copies of one path per card).

Shapes are defined once now and referenced with `<use>`. The whole icon set is 5.6 KB of path data, so emitting all of it beats working out which subset a page needs. The six presentation attributes on every icon moved to a CSS class. Testimonial wall carries six of nine per column rather than all nine.

**342 KB → 262 KB.**

### App cards, and the tap problem (`b3c5b43`)

Opening an app card took **~2.7 s**: a 1 s spin, a 620 ms flood, a 460 ms wait, a full document load, then 1.2 s of splash on the page that arrived.

The splash was the bulk and pure waste — the flood already covered the screen, so the next page put up a *second* loading animation. It now shows **once per session, on arrival only**. It used to hook `astro:before-preparation`, so every in-site click raised a full-screen white hold before the page appeared — which read as a dead link, and had people tapping two and three times.

Two more taps were being lost in the marquee itself: the strip only paused on `:hover`, which touch never fires, so the logo slid out from under the finger and the browser discarded the click as a drag.

**~2.7 s → ~0.9 s.**

### Legal pages (`6a6e52a`)

All three translated into all eight non-English locales — **24 new files**, 2,311 English words becoming ~18,500.

No code changed. `getLocalized` already resolved `src/content/legal/<locale>/<slug>.md` with an English fallback; the architecture was there and unpopulated. Every file matches the English structure exactly — 18 `h2`, 6 `ul`, 23 `li`, 12 `strong`, one `code`, and identical counts for all eight placeholders.

The updated date is now a real date formatted per locale, in the two-tone pill the 369 site uses. Worth noting: **369's pill has no animation** — it never opts into its own reveal system. The effect is the treatment.

> ⚠️ **These are binding documents.** Terms of art — "data fiduciary", "lawful basis", the DPDP references — do not always survive translation with their legal force intact. A native speaker or a lawyer should read the Arabic and the four Indian-language versions before they are relied on.

### Speed (`7f5982c`, `f9016be`)

**Language switching was the slowest path on the site.** The nine locale links carried `data-astro-prefetch="false"` while every other link was being prefetched, then did a full load from cold. Now `hover` — the page is fetched as your pointer reaches a language. `data-astro-reload` stays, because a locale change must rewrite `<html lang>` and `dir`.

**HTML was cached nowhere.** Every page view woke the Worker; the live site shows `cf-cache-status: DYNAMIC`. `public/_headers` now holds pages at the edge for 10 minutes with stale-while-revalidate.

> The `/_astro/* immutable` rule had to be written out by hand. The adapter injects it **only** while generating the file from scratch — the moment a source `public/_headers` exists it stops, and the year-long asset caching disappears silently. The first build proved it: `dist/client/_headers` came out with `/*` alone.

### Promo deck (`7e79783`)

Three cards — apps, ERP modules, 369 devices — in the corner, one at a time. Auto-advances every 5 s; an arrow or dot stops it **for good**, because taking control back off someone who just took it is hostile. Hover and focus pause it. 15 s before it appears, dismissed for a day. Renders `hidden` so JS-off never sees a promo whose dismiss button does nothing.

The footer's back-to-top moved to a logical edge in the same commit — one physical edge and one logical edge would have put them in the same corner in Arabic.

## Things I got wrong

Recorded because they cost you time.

**I broke your dev server three times** by deleting caches while it was running — `node_modules/.vite` once, `.astro/data-store.json` twice. Each time it took a restart to recover. The sharper rule, now saved: never touch `.astro/` at all. `npm run build` writes to a *different* store, so deleting that one never once helped a build I was running.

**I wrote `:global()` inside a `<style is:global>` block** (`6f28094`). Astro only strips `:global()` from *scoped* styles; in an already-global block it reaches the stylesheet verbatim, where it is invalid. lightningcss dropped the rule — so the progress bar filled from the wrong side in Arabic — **and it killed your build**, which stopped after "Building server entrypoints" without prerendering anything. The warning was in your output and I had read past it.

**I put a comment inside a JSX attribute list**, where it is an expression container. The apostrophe in "Astro's" read as the start of a string literal and `astro check` failed with two errors.

**I let you compare a dev server to a live CDN for hours.** `astro dev` re-renders every page through miniflare on each request; measured on the same pages, dev was 3.5–8.6 s and the built output **4 ms**. Roughly 800×. The site was never slow. I should have established *where* you were testing before optimising anything.

**And I designed the promo deck four or five times without building it.** Each time we settled a detail a new message arrived and I switched to that instead.

## How to run it

`astro preview` does **not** watch for changes, and it snapshots the asset manifest at startup. Rebuild without restarting it and you get fresh HTML pointing at stylesheets it refuses to serve — which is the unstyled black shape you saw. Always run them as a pair:

```powershell
npm run build; if ($?) { npm run preview }
```

PowerShell 5.1 has no `&&`. Stop the dev server first — preview wants the same port.

**To test the promo deck:** wait 15 s on any page. To make it reappear after dismissing:

```js
localStorage.removeItem('alphalize:promo'); location.reload()
```

**To test right-to-left:** visit `/ar`. The `?dir=rtl` helper is dev-only and stripped from production builds.
